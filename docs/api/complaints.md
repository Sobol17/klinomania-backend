# Жалобы API

Все endpoints требуют Bearer token пользователя с ролью `client`.

## Подать жалобу

`POST /api/v1/client/orders/{public_id}/complaints`

Жалобу может подать только владелец заявки. Допустимые статусы заявки: `in_progress`,
`awaiting_payment`, `completed`. Для остальных статусов сервер возвращает `409` с кодом
`complaint_not_allowed`. Несуществующая заявка возвращает `404`, чужая — `403`.

Request:

```json
{
  "subject": "Повреждена мебель",
  "message": "После уборки обнаружена царапина на столе."
}
```

Response `201`:

```json
{
  "data": {
    "id": 15,
    "order_id": "01J2QM1R7H7YV9JH1KACD6ZK3R",
    "status": "new",
    "status_label": "Новая",
    "subject": "Повреждена мебель",
    "message": "После уборки обнаружена царапина на столе.",
    "admin_comment": null,
    "resolved_at": null,
    "created_at": "2026-09-09T04:00:00Z",
    "updated_at": "2026-09-09T04:00:00Z"
  }
}
```

Частота подачи ограничена пятью запросами в минуту на клиента. При превышении сервер
возвращает `429` с кодом `rate_limited`. Число жалоб по одной заявке не ограничено.

## Список жалоб клиента

`GET /api/v1/client/complaints`

Возвращает только жалобы авторизованного клиента, новые первыми. Формат каждого элемента
совпадает с объектом `data` ответа создания.

## Статусы жалобы

- `new` — новая;
- `in_progress` — администратор взял жалобу в работу;
- `resolved` — жалоба решена;
- `rejected` — жалоба отклонена.

При статусах `resolved` и `rejected` клиенту возвращаются комментарий администратора и дата
обработки.
