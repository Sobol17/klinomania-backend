## Цель

Администратор видит чек-лист по заказу, ведёт пункты шаблона услуги и контролирует выполнение.

## Текущее состояние

Чек-листы **двухуровневые**, и это главный источник недопонимания в ТЗ:

**Уровень 1 — шаблон услуги.** `service_checklist_items` (`cleaning_service_id`, `zone`, `title`,
`sort_order`), модель `ServiceChecklistItem`, зона — `App\Enums\ChecklistZone`
(`all` «Везде», `rooms` «Комнаты, гардеробная и прихожая», `kitchen` «Кухня», `bathroom` «Санузел»;
у enum уже есть метод `label()`). Редактируется в `CleaningServiceResource` вкладками с репитерами.

**Уровень 2 — экземпляры по заказу, и их два разных типа:**

- `order_checklist_items` (`OrderChecklistItem`) — пункты из шаблона услуги, связь
  `service_checklist_item_id`, уникальная пара с заказом;
- `order_extra_checklist_items` (`OrderExtraChecklistItem`) — пункты по **доп. работам**, связь
  не с шаблоном, а с `order_line_item_id` (позиция заказа с `kind = 'extra_option'`).

Обе таблицы имеют `completed_at` и `completed_by` (FK на `users`, `nullOnDelete`) и `$guarded = []`.

Клинер отмечает пункты через `PATCH /api/v1/cleaner/orders/{order}/checklist/{item}`
(`CleanerOrderController::updateChecklistItem()`); группировка по зонам для мобильного клиента —
в приватном `checklistSections()`.

`OrderWorkflow::complete()` не даёт завершить заказ, пока остались незакрытые пункты
любого из двух типов: два отдельных запроса `whereDoesntHave`, при нарушении — 409
с кодом `checklist_incomplete`.

**В админке экземпляры по заказу недоступны вообще** — виден только шаблон услуги.

## Объём работ

- [ ] Секция чек-листа в карточке заказа: группировка по зонам через `ChecklistZone::label()`,
      отдельный блок «Дополнительные работы» для `OrderExtraChecklistItem`.
- [ ] По каждому пункту: название, признак выполнения, кто и когда выполнил
      (`completed_by`, `completed_at`).
- [ ] Индикатор прогресса «выполнено X из Y», считающий **обе** таблицы.
- [ ] Действие отметки и снятия отметки администратором: `completed_at` = `now()`/`null`,
      `completed_by` = текущий администратор.
- [ ] Вынести общую логику группировки по зонам из `CleanerOrderController::checklistSections()`
      в переиспользуемое место, чтобы панель и API показывали одинаковую структуру.
- [ ] Улучшить редактирование шаблонов в `CleaningServiceResource`: показывать число пунктов
      по зонам, предупреждать, что изменения шаблона не влияют на уже созданные заказы.
- [ ] Нотификация при попытке завершить заказ с незакрытым чек-листом — понятная, с указанием
      числа оставшихся пунктов.

## Критерии приёмки

1. В карточке заказа виден чек-лист, сгруппированный по зонам, и отдельный блок доп. работ.
2. По каждому пункту видно, выполнен ли он, кем и когда.
3. Прогресс показывает суммарное число выполненных и общее число пунктов обоих типов.
4. Администратор отмечает и снимает отметку; `completed_by` записывает именно администратора.
5. Пункты шаблона услуги создаются, правятся, удаляются и переупорядочиваются по зонам.
6. Изменение шаблона не меняет чек-листы уже созданных заказов — проверяется тестом.
7. Попытка завершить заказ с незакрытым чек-листом отклоняется с указанием числа оставшихся пунктов.

  доп. пунктом не завершается.

## Риски

- **Второй тип пунктов легко упустить.** `OrderExtraChecklistItem` живёт в другой таблице и
  связан с позицией заказа, а не с шаблоном. Заказ с доп. работами обязателен в тестовых данных.
- Ручная отметка администратором вместо клинера меняет смысл поля `completed_by` — раньше там
  всегда был исполнитель. Отразить в интерфейсе, чтобы отчётность по клинерам не искажалась.
- Шаблоны и экземпляры не синхронизируются: пункт, добавленный в услугу после создания заказа,
  в этом заказе не появится. Это текущее поведение системы, менять его в рамках эпика не нужно,
  но администратора надо предупредить в интерфейсе.
