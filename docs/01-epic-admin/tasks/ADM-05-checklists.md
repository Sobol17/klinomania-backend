## Цель

Администратор видит чек-лист по заказу, ведёт пункты шаблона услуги и контролирует выполнение.

## Решение по объёму

По уточнению заказчика текущая бизнес-логика чек-листов и мобильный API работают правильно и
не меняются в ADM-05. Задача ограничена интерфейсом администратора: удобное чтение прогресса,
группировка по зонам, отдельные дополнительные работы и более понятный редактор шаблона.
Администратор не получает новых действий отметки/снятия пунктов или завершения заказа.

Текущий шаблон услуги является живым: изменения после сохранения видны во всех заказах услуги,
а удаление шаблонного пункта каскадно удаляет историю его отметок. Интерфейс предупреждает об этом
фактическом поведении; механизм снимков в рамках задачи не вводится.

## Текущее состояние

Чек-листы **двухуровневые**, и это главный источник недопонимания в ТЗ:

**Уровень 1 — шаблон услуги.** `service_checklist_items` (`cleaning_service_id`, `zone`, `title`,
`sort_order`), модель `ServiceChecklistItem`, зона — `App\Enums\ChecklistZone`
(`all` «Везде», `rooms` «Комнаты, гардеробная и прихожая», `kitchen` «Кухня», `bathroom` «Санузел»;
у enum уже есть метод `label()`). Редактируется в `CleaningServiceResource` вкладками с репитерами.

**Уровень 2 — экземпляры по заказу, и их два разных типа:**

- `order_checklist_items` (`OrderChecklistItem`) — пункты из шаблона услуги, связь
  `service_checklist_item_id`, уникальная пара с заказом;
- `order_extra_checklist_items` (`OrderExtraChecklistItem`) — пункты по **доп. работам**, связь
  не с шаблоном, а с `order_line_item_id` (позиция заказа с `kind = 'extra_option'`).

Обе таблицы имеют `completed_at` и `completed_by` (FK на `users`, `nullOnDelete`) и `$guarded = []`.

Клинер отмечает пункты через `PATCH /api/v1/cleaner/orders/{order}/checklist/{item}`
(`CleanerOrderController::updateChecklistItem()`); группировка по зонам для мобильного клиента —
в приватном `checklistSections()`.

`OrderWorkflow::complete()` не даёт завершить заказ, пока остались незакрытые пункты
любого из двух типов: два отдельных запроса `whereDoesntHave`, при нарушении — 409
с кодом `checklist_incomplete`.

До ADM-04 экземпляры по заказу были недоступны. ADM-05 превращает техническую таблицу в понятный
маршрут уборки, не меняя способ хранения или выполнения пунктов.

## Объём работ

- [x] Секция чек-листа в карточке заказа: группировка по зонам через `ChecklistZone::label()`,
      отдельный блок «Дополнительные работы» для `OrderExtraChecklistItem`.
- [x] По каждому пункту: название, признак выполнения, кто и когда выполнил
      (`completed_by`, `completed_at`).
- [x] Визуальный индикатор прогресса «выполнено X из Y», считающий шаблонные пункты и доп. работы:
      общая полоса, процент и сегменты по зонам в заявке; компактный индикатор также добавлен в список заказов.
- [x] Улучшить редактирование шаблонов в `CleaningServiceResource`: показывать число пунктов
      по зонам, добавить доступное переупорядочивание кнопками и честно предупреждать о влиянии
      изменений на существующие заказы и историю отметок.
- [x] Сохранить текущую бизнес-логику: без админской отметки пунктов, новых переходов статуса
      и изменений `CleanerOrderController` или публичного API.

## Критерии приёмки

1. В карточке заказа виден чек-лист, сгруппированный по зонам, и отдельный блок доп. работ.
2. По каждому пункту видно, выполнен ли он, кем и когда.
3. Прогресс показывает суммарное число выполненных и общее число пунктов обоих типов.
4. Пункты шаблона услуги создаются, правятся, удаляются и переупорядочиваются по зонам; вкладки
   показывают число пунктов и предупреждают о последствиях изменения.
5. Админский UI не изменяет отметки выполнения и статус заказа; существующие мобильные сценарии
   и ответы API остаются без изменений.

## Риски

- **Второй тип пунктов легко упустить.** `OrderExtraChecklistItem` живёт в другой таблице и
  связан с позицией заказа, а не с шаблоном. Заказ с доп. работами обязателен в тестовых данных.
- Новые права администратора на отметку пунктов исказили бы смысл `completed_by`, поэтому такие
  действия не добавляются.
- Шаблон используется заказами напрямую. Неверное обещание о «снимке» скрывало бы
  влияние правок; интерфейс явно предупреждает о текущем живом поведении.
