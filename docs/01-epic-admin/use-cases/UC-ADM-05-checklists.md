# Use cases — ADM-05. Управление чек-листами

Задача: [ADM-05](../tasks/ADM-05-checklists.md) · Пункт ТЗ: 1.5

Напоминание об устройстве: **шаблон** услуги — `service_checklist_items` (с зонами);
**экземпляры по заказу** — две разные таблицы: `order_checklist_items` (пункты из шаблона)
и `order_extra_checklist_items` (пункты по доп. работам, привязанные к `order_line_item_id`).

---

## UC-5.1 — Просмотр чек-листа по заказу

**Актор:** администратор

**Основной сценарий**
1. Администратор открывает карточку заказа.
2. В блоке чек-листа видит пункты, сгруппированные по зонам:
   «Везде», «Комнаты, гардеробная и прихожая», «Кухня», «Санузел» (`ChecklistZone::label()`).
3. Отдельным блоком «Дополнительные работы» видит пункты из `order_extra_checklist_items`.
4. По каждому пункту видит признак выполнения, исполнителя (`completed_by`) и время (`completed_at`).

**Альтернативные потоки**
- 2a. У услуги нет пунктов чек-листа → блок показывает пустое состояние.
- 3a. В заказе нет доп. работ → блок доп. работ скрыт.
- 4a. Пункт не выполнен → поля исполнителя и времени пусты.

**Критерии приёмки**
- Given заказ по услуге с чек-листом, When открыта карточка, Then пункты сгруппированы по зонам с русскими названиями.
- Given заказ содержит доп. работы, When открыта карточка, Then они показаны отдельным блоком.
- Given пункт выполнен клинером, When открыт чек-лист, Then видно, кто и когда его выполнил.

## UC-5.2 — Создание и редактирование пунктов шаблона чек-листа

**Актор:** администратор

**Основной сценарий**
1. Администратор открывает услугу и переходит к чек-листам.
2. Видит вкладки по четырём зонам.
3. Добавляет пункт: название и зона; редактирует или удаляет существующие.
4. Сохраняет.

**Альтернативные и исключительные потоки**
- 4a. Изменения шаблона **не влияют на уже созданные заказы** — их чек-листы зафиксированы
  в момент создания. Интерфейс явно предупреждает об этом.
- 3a. Удаление пункта шаблона: записи `order_checklist_items` связаны каскадно,
  поэтому удаление затронет историю уже созданных заказов — требуется подтверждение
  с явным предупреждением.

**Критерии приёмки**
- Given открыта услуга, When добавлен пункт в зону «Кухня», Then он сохранён с `zone = kitchen`.
- Given существует заказ по этой услуге, When в шаблон добавлен новый пункт, Then чек-лист существующего заказа не изменился.
- Given администратор удаляет пункт шаблона, When действие выполняется, Then показано предупреждение о влиянии на историю заказов.

## UC-5.3 — Управление порядком и зонами пунктов

**Актор:** администратор

**Основной сценарий**
1. Администратор открывает вкладку зоны.
2. Меняет порядок пунктов перетаскиванием (`sort_order`).
3. При необходимости переносит пункт в другую зону сменой поля `zone`.
4. Сохраняет.

**Альтернативные потоки**
- 3a. Перенос между зонами меняет группировку в мобильном приложении клинера —
  структура берётся из тех же данных.

**Критерии приёмки**
- Given несколько пунктов в зоне, When порядок изменён перетаскиванием и сохранён, Then он сохраняется после перезагрузки.
- Given пункт перенесён в другую зону, When изменения сохранены, Then он отображается в новой зоне и в панели, и в API клинера.

## UC-5.4 — Отметка выполнения пункта администратором

**Актор:** администратор

**Основной сценарий**
1. Администратор открывает чек-лист заказа.
2. Отмечает пункт как выполненный.
3. Система записывает `completed_at = now()` и `completed_by` = идентификатор администратора.
4. Прогресс пересчитывается.

**Альтернативные и исключительные потоки**
- 2a. Снятие отметки → `completed_at = null`, `completed_by = null`.
- 2b. Пункт доп. работ отмечается тем же способом, но в таблице `order_extra_checklist_items`.
- 3a. Заказ в статусе `completed` → изменение отметок запрещено.
- 3b. В `completed_by` попадает администратор, а не клинер — это меняет смысл поля,
  которое раньше всегда содержало исполнителя. Интерфейс должен отражать это,
  чтобы отчётность по клинерам не искажалась.

**Критерии приёмки**
- Given невыполненный пункт, When администратор его отмечает, Then `completed_at` заполнен и `completed_by` указывает на администратора.
- Given выполненный пункт, When отметка снята, Then оба поля обнулены и прогресс пересчитан.
- Given заказ в статусе `completed`, When открыт чек-лист, Then отметки изменить нельзя.

## UC-5.5 — Контроль прогресса выполнения чек-листа

**Актор:** администратор

**Основной сценарий**
1. Администратор открывает карточку заказа.
2. Видит индикатор «выполнено X из Y», где Y — **сумма** пунктов
   `order_checklist_items` и `order_extra_checklist_items`.
3. Видит прогресс в разрезе зон.

**Альтернативные потоки**
- 2a. Пунктов нет вообще → индикатор скрыт.
- 2b. Все пункты выполнены → индикатор помечен как завершённый.
- 3a. Колонка прогресса доступна и в списке заказов для заказов в работе.

**Критерии приёмки**
- Given заказ с 10 пунктами шаблона и 2 доп. работами, из которых выполнено 5, When открыта карточка, Then индикатор показывает «5 из 12».
- Given все пункты выполнены, When открыта карточка, Then прогресс помечен как завершённый.
- Given заказ без пунктов, When открыта карточка, Then индикатор не отображается.

## UC-5.6 — Блокировка завершения заказа при незакрытом чек-листе

**Актор:** клинер (правило контролируется администратором)

**Основной сценарий**
1. Клинер вызывает завершение заказа.
2. `OrderWorkflow::complete()` проверяет **оба** типа пунктов: пункты шаблона услуги
   и позиции с `kind = 'extra_option'`.
3. Все пункты закрыты → заказ переходит в `awaiting_payment`.

**Альтернативные и исключительные потоки**
- 3a. Есть незакрытые пункты → отказ с кодом `checklist_incomplete`; в API это 409,
  в панели — нотификация с указанием числа оставшихся пунктов.
- 3b. Закрыты все пункты шаблона, но остались доп. работы → завершение всё равно отклоняется.
  **Это самый вероятный пропущенный сценарий**, он обязателен в тестах.
- 1a. Администратор может разблокировать завершение, отметив оставшиеся пункты сам (UC-5.4).

**Постусловия:** заказ не завершается, пока чек-лист не закрыт полностью.

**Критерии приёмки**
- Given заказ с незакрытым пунктом шаблона, When клинер завершает заказ, Then ответ 409 с кодом `checklist_incomplete`.
- Given все пункты шаблона закрыты, но осталась незакрытая доп. работа, When клинер завершает заказ, Then завершение отклонено.
- Given администратор отметил оставшиеся пункты, When клинер повторяет завершение, Then заказ переходит в `awaiting_payment`.
