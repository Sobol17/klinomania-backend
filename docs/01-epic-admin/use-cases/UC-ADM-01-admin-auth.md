# Use cases — ADM-01. Авторизация и доступ администратора

Задача: [ADM-01](../tasks/ADM-01-admin-auth.md) · Пункт ТЗ: 1.1

## UC-1.1 — Вход администратора в систему

**Актор:** администратор
**Предусловия:** учётная запись с `role = admin` и `status = active` существует; панель развёрнута и доступна по HTTPS.

**Основной сценарий**
1. Администратор открывает `https://<домен>/admin`.
2. Система, не найдя активной сессии, перенаправляет на `/admin/login`.
3. Администратор вводит email и пароль и подтверждает вход.
4. Система проверяет учётные данные по гварду `web`, затем вызывает `User::canAccessPanel()`.
5. Проверки пройдены: создаётся сессия, администратор попадает на дашборд.

**Альтернативные и исключительные потоки**
- 3a. Неверный email или пароль → сообщение об ошибке без указания, что именно неверно; сессия не создаётся.
- 4a. Роль не `admin` → см. UC-1.2.
- 4b. Статус `blocked` → см. UC-1.5.
- 3b. Превышен лимит попыток → см. UC-1.6.

**Постусловия:** активная сессия администратора; доступны все разделы панели.

**Критерии приёмки**
- Given активный администратор, When он вводит верные email и пароль на `/admin/login`, Then он попадает на дашборд `/admin`.
- Given неверный пароль, When отправлена форма, Then показана ошибка и сессия не создана.

**Связанные:** UC-1.2, UC-1.5, UC-1.6

## UC-1.2 — Отказ в доступе пользователю без роли администратора

**Актор:** клиент или клинер
**Предусловия:** у пользователя есть учётная запись с ролью `client` или `cleaner` и заданным паролем.

**Основной сценарий**
1. Пользователь открывает `/admin/login` и вводит свои верные учётные данные.
2. Система аутентифицирует его и вызывает `User::canAccessPanel()`.
3. Метод возвращает `false`, потому что роль не `UserRole::Admin`.
4. Система отказывает в доступе и не создаёт сессию панели.

**Альтернативные потоки**
- 4a. Пользователь пытается открыть внутренний URL панели напрямую → тот же отказ.

**Постусловия:** доступ к панели не получен; работа мобильного API для этого пользователя не затронута.

**Критерии приёмки**
- Given пользователь с ролью `client` и верным паролем, When он входит на `/admin/login`, Then он не попадает в панель.
- Given пользователь с ролью `cleaner`, When он открывает `/admin/cleaning-orders` напрямую, Then доступ отклонён.
- Given любой из них, When доступ отклонён, Then его токены Sanctum и работа мобильного приложения не затронуты.

**Связанные:** UC-1.1

## UC-1.3 — Перенаправление неавторизованного пользователя

**Актор:** неавторизованный посетитель

**Основной сценарий**
1. Посетитель открывает произвольный URL панели, например `/admin/users`.
2. Middleware `Authenticate` не находит сессии.
3. Система перенаправляет на `/admin/login`.

**Альтернативные потоки**
- 3a. После успешного входа система возвращает посетителя на изначально запрошенный URL.

**Постусловия:** содержимое панели неавторизованному не показано.

**Критерии приёмки**
- Given отсутствие сессии, When запрошен любой URL панели, Then происходит редирект на `/admin/login` и данные не раскрываются.
- Given редирект с сохранением адреса, When вход выполнен, Then открывается изначально запрошенная страница.

## UC-1.4 — Выход из панели

**Актор:** администратор
**Предусловия:** активная сессия.

**Основной сценарий**
1. Администратор выбирает «Выйти» в меню профиля.
2. Система завершает сессию и перегенерирует токен сессии.
3. Происходит переход на `/admin/login`.

**Альтернативные потоки**
- 3a. Возврат «назад» в браузере не показывает содержимое панели — только форму входа.

**Постусловия:** сессия недействительна.

**Критерии приёмки**
- Given активная сессия, When администратор выходит, Then он оказывается на форме входа.
- Given выполненный выход, When нажата кнопка «назад» в браузере, Then содержимое панели не отображается.

## UC-1.5 — Отказ заблокированному администратору

**Актор:** заблокированный администратор
**Предусловия:** `users.status = blocked` (поле создаётся в [ADM-02](../tasks/ADM-02-users.md)).

**Основной сценарий**
1. Администратор вводит верные учётные данные.
2. `User::canAccessPanel()` проверяет роль и статус.
3. Статус `blocked` → доступ отклонён.

**Альтернативные потоки**
- 3a. Администратор был заблокирован во время активной сессии → следующий запрос к панели отклоняется.

**Постусловия:** доступ не получен; после снятия блокировки (UC-2.8) вход снова возможен.

**Критерии приёмки**
- Given администратор со статусом `blocked` и верным паролем, When он входит, Then доступ отклонён.
- Given администратор заблокирован при активной сессии, When он выполняет следующий запрос, Then сессия прекращается.

**Связанные:** UC-2.7, UC-2.8

## UC-1.6 — Ограничение попыток подбора пароля

**Актор:** злоумышленник

**Основной сценарий**
1. С одного адреса подряд отправляются неверные пароли для одного email.
2. Система считает неудачные попытки по паре email + IP.
3. По достижении порога дальнейшие попытки отклоняются на заданный интервал.

**Альтернативные потоки**
- 3a. По истечении интервала счётчик сбрасывается.
- 2a. Успешный вход до достижения порога сбрасывает счётчик.

**Постусловия:** перебор пароля через форму входа непрактичен.

**Критерии приёмки**
- Given достигнут порог неудачных попыток, When отправлена ещё одна, Then она отклоняется с указанием времени ожидания.
- Given порог достигнут для одного email, When вход выполняет другой администратор, Then он не заблокирован.
