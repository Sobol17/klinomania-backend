## Порядок выполнения

```
ADM-08 (каркас: enum-классы, доменные исключения, политики)
   │
   ├─► ADM-01 (авторизация)
   │
   ├─► ADM-02 (пользователи) ──► ADM-01 UC-1.5 (отказ заблокированному админу)
   │
   ├─► ADM-04 (заказы) ──► ADM-05 (чек-листы по заказу)
   │
   ├─► ADM-03 (услуги)
   │
   ├─► ADM-06 (жалобы: БД + API + админка)
   │
   └─► ADM-07 (оплаты)
              │
              ▼
   ADM-08, вторая часть (приёмка по ТЗ, передача кода)
```

ADM-08 сознательно разорвана: каркас блокирует почти всё и делается первым,
приёмка и передача кода — последними.

## Как читать

Начинать с [00-epic.md](00-epic.md) — там словарь соответствий между терминами ТЗ и
реальными именами в коде (`CleaningOrder` вместо `Order`, `PaymentAttempt` вместо `Payment`
и т.д.), без него постановки читаются неверно.

Что важно знать до планирования спринта:

- панель **уже частично существует** — Filament 5.6.8, четыре ресурса, вход только для роли Admin;
- **домена жалоб нет вообще**, ADM-06 включает миграцию, модель, API и уведомления;
- у `users` **нет поля статуса** — ADM-02 включает миграцию;
- **оплаты read-only** — подтверждено заказчиком, см. «Согласованные решения» в эпике;
- **жалоба принимается только** когда заявка выполняется или выполнена
  (`in_progress`, `awaiting_payment`, `completed`).

## Соглашения

- **ID задач:** `ADM-NN`. **ID use cases:** `UC-N.M`, где `N` — номер задачи.
- Имена классов, таблиц и полей приводятся так, как они есть в коде.
- Сущности, которых ещё нет, помечены «создаётся в ADM-NN».
- Критерии приёмки use cases сформулированы в Given / When / Then.
